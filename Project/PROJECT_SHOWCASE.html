  • modules: Enforces unique constraint on (course_id, title) to guarantee repeatable academic structure.

Vector Engineering

pgvector & HNSW Graph Indexing

How the system resolves semantic similarity queries at scale without CPU bottlenecks:

  • Cosine Distance Operator: Uses <=> for directional semantic matching independent of length.
  • HNSW Parameters: Configured with m = 16 (edges per node) and ef_construction = 64 for >98% recall.
  • Sub-Millisecond Search: Skip-list routing navigates multi-layer vector graphs in $O(\log N)$ time.

Oral Defense

Professor & Evaluator Viva Defense Q&A

Exact technical answers to the most common questions professors ask during project evaluations.

CO1: Relational DB Why did you use Boyce-Codd Normal Form (BCNF) instead of just 3NF?
▼
"While 3NF eliminates transitive dependencies for non-prime attributes, it still allows redundancy if a prime attribute is functionally dependent on a non-superkey. In our course schedule mapping, multiple instructors teach the same course code across semesters. Decomposing to BCNF guarantees that every determinant in every functional dependency is strictly a candidate superkey, eliminating all update anomalies while preserving lossless joins."
CO2: Vector DB Why did you choose HNSW over IVFFlat for vector search in PostgreSQL?
▼
"IVFFlat requires an initial training step to cluster vectors into Voronoi cells; as new course content is added later, centroid skew degrades search quality unless the index is rebuilt. HNSW (Hierarchical Navigable Small World) builds a multi-layer skip-list graph dynamically upon insert. It provides superior recall (>98%), supports incremental real-time inserts without retraining, and searches in O(log N) time with low latency."
CO3: FastAPI Why did you use FastAPI over Django or Flask for the backend?
▼
"FastAPI is an asynchronous ASGI framework running on the uvloop event loop, allowing a single worker to handle thousands of concurrent I/O-bound database requests without blocking threads. Furthermore, its integration with Pydantic v2 (compiled in Rust) provides 10x faster data serialization and automatic OpenAPI documentation generation with zero boilerplate."
CO4: Multi-Framework What is the advantage of having both a FastAPI and a Node.js backend?
▼
"It demonstrates multi-framework backend competency and decouples dependencies. The FastAPI service leverages Python's scientific ecosystem (Scikit-Learn, PyTorch, NumPy) for embedding generation and ML model inference. The Node.js Express service utilizes libuv's non-blocking I/O event loop to serve lightweight JSON APIs with zero Python runtime dependencies for offline presentations."
CO5: Microservices How does your system handle distributed failures across services?
▼
"We implement the Saga Pattern and graceful degradation. When upstream services communicate, they use timeout thresholds and exponential backoff with jitter. If a downstream vector search or external store fails, the system executes a fallback to pre-indexed textbook knowledge chunks, ensuring students always receive an academic answer rather than a raw 500 error."
CO6: Testing How do you prove your system works correctly under test?
▼
"We implemented automated test suites using pytest in `backend/tests/` covering database connections, JWT authentication, course catalog queries, and RAG answer synthesis. We generated coverage reports in `backend/htmlcov/` verifying endpoint execution and schema contracts."
